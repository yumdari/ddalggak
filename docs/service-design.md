# 딸깍 서비스 설계

## 제품 목표

대학생이 여러 사이트를 돌며 공모전·장학금을 찾지 않아도, 서비스가 공고를 모아 관심 분야·학년·지역에 맞는 기회를 먼저 보여준다. 사용자는 추천 이유와 출처를 확인하고 공식 원문에서 신청한다. 검색은 보조 기능이다.

## 핵심 흐름

```text
공식 출처 RSS·API → 수집 후보 → 중복 확인·관리자 검수 → 게시 공고
                                                    ↓
사용자 관심 분야·학년·지역 → 자격 조건 대조·추천 순위 → 맞춤 피드 → 공식 원문
```

출처별 수집 어댑터를 추가한다. 출처에서 확실히 제공하지 않은 자격·마감 시각을 추정해 게시하지 않는다. RSS처럼 제목과 링크 중심인 출처는 후보로 저장하고, 관리자가 원문을 확인해 구조화한다. 게시된 공고의 원문 링크와 마지막 확인 시각을 사용자에게 보여준다. 수집이 실패해도 기존 공고를 자동 삭제하거나 덮어쓰지 않는다.

## 첫 출시 범위

1. 둘 이상의 허용된 출처에서 공고를 주기적으로 가져오고 중복 URL을 걸러 검수함에 저장한다.
2. 관리자가 원문과 자격·혜택·신청 방법·마감을 비교해 게시하거나 후보를 제외한다.
3. 회원이 관심 분야·학년·지역을 저장한다.
4. 알려진 학년·지역 불일치와 마감 공고를 제외하고, 관심 분야가 맞는 공고를 위에 보여준다. 조건이 비어 있으면 추천 범위를 넓히되 자격 충족을 보장한다고 표현하지 않는다.
5. 추천 이유, 원문 출처, 마지막 확인 시각, 마감 정보의 정확도, 관심 공고 저장을 제공한다.

첫 구현은 RSS/Atom 수집, 검수함, 규칙 기반 추천, 회원 프로필, 맞춤 피드와 관심 공고를 제공한다. 실제 운영 출처 목록과 갱신 주기는 결정 후 등록한다. 수집 어댑터 확장, 자동 분류, 변경 감지, 알림은 후속 단계다.

## 사용자와 관리자 화면

| 화면 | 주요 내용 |
| --- | --- |
| 맞춤 피드 | 추천 공고, 일치 이유, 모집 상태, 마감, 공식 원문 |
| 내 조건 | 관심 분야, 학년, 지역 |
| 관심 공고 | 저장한 공고와 마감 상태 |
| 검수함 | 수집한 제목·내용·원문, 분류·자격·마감 입력, 게시·제외 |

검색·필터는 공고량이 늘어난 뒤 보조 탐색으로 추가한다. 핵심 첫 화면은 맞춤 피드다.

## 데이터와 추천 규칙

- `sources`: 출처 이름과 피드 URL, 활성 상태.
- `import_candidates`: 원문 URL, 수집 제목·내용·시각, 검수 상태. 같은 정규화 URL은 중복 저장하지 않는다.
- `opportunities`: 검수된 유형, 제목, 기관, 자격, 혜택, 신청 방법, 지역, 학년, 태그, 모집 상태, 출처와 확인 시각.
- `users`: 계정과 관심 분야·학년·지역. 회원 가입 때 입력을 강제하지 않는다.
- `bookmarks`: 회원·공고 조합을 유일하게 저장한다.
- `audit_events`: 게시와 숨김 기록.

추천은 게시 공고 중 마감되지 않은 항목에서 시작한다. 확인된 학년·지역 제한과 사용자 조건이 명백히 어긋나면 제외한다. 관심 분야가 겹치는 수, 학년·지역 일치 여부로 정렬하고 이유를 표시한다. 정보가 없는 조건은 `제한 없음`으로 해석하지 않는다. 전공, 소득, 학교 같은 복잡한 자격은 자동 판정하지 않고 원문 자격 설명을 보여준다.

마감은 `datetime`, `date_only`, `always_open`, `unknown`으로 구분한다. 시각이 확인된 경우에는 시간대를 저장하고 한국 시간으로 표시한다. 날짜만 확인되면 임의의 종료 시각을 표시하지 않는다. 상시 모집과 마감 미정은 구분한다.

## 운영 결정 사항

- 첫 공식 출처의 범위와 각 사이트 이용 조건
- 특정 대학 전용 공고의 노출 대상과 학교 인증 여부
- 수집 주기, 후보 검수 인력, 오래된 공고 재확인 주기
- 알림 채널과 발송 시점

첫 수집 예제로 [가천대학교 장학공지 RSS](https://www.gachon.ac.kr/bbs/kor/478/rssList.do?row=50)를 확인했다. 해당 피드는 대학 전용 공고도 포함하므로, 대학별 노출 정책을 정하기 전에는 전체 사용자에게 자동 게시하지 않는다.
